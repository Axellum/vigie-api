# 0001. Two repositories, no fabricated data, a text frame

- Status: accepted
- Date: 2026-10-20

## Context

Vigie has two parts: an ESP32-P4 display firmware (C++, repository `vigie-display`) and this
API (Python, running on a PC at home). The display is a warning device; a wrong number on it is
worse than a missing one. The first versions of the API filled every gap with a plausible value
(a temperature computed from the latitude, `22` as air quality, a rain probability derived from
the rain amount, `2.0` as the Kp index when the file could not be read), labelled the result
with a real provider name, and sent it as if it were measured.

## Decision

1. **Two repositories.** The firmware renders; the API collects, normalizes and decides what is
   known. The firmware does not call any provider. The only interface is the text frame.
2. **No fabricated data, ever.** A value the providers do not supply is *unknown*: `null` in
   JSON, an **empty field** in the frame. No default number, no value copied from another field,
   no value computed from something unrelated. If every weather source fails, the zone has no
   weather. If every hazard source fails, the global status is unknown, not `GREEN`. Simulated
   data exists for testing only and is always labelled. The display decides how to show
   "unknown" (for example `--`).
3. **A line-based text frame**, `HEAD|`, `ZONE|`, `RAIN5M|`, `DAY|`, `HAZ|`, `END|<CRC32>`:
   decodable in one pass without dynamic allocation, easy to read and to capture as a test
   fixture, protected by a CRC32. Fixed column order and count per line type; empty = unknown.
   Dates are ISO 8601, so the firmware formats the day names in its own language.
4. **The contract has one source:** [`docs/embedded-frame.md`](../embedded-frame.md), pinned by
   `tests/test_embedded_frame_contract.py` (the document's example is generated by the code and
   compared by a test). A change of the frame changes that document, its tests and the display
   decoder together.

## Consequences

- The display must keep empty fields when it splits a line (no `strtok`) and handle "unknown"
  for every numeric column.
- Some screens will show "no data" more often than before. That is intended.
- Providers that lack a variable leave it empty (MET Norway: no gust, UV, apparent temperature,
  nowcast). Empty is accepted rather than approximated.
- The frame has no field for "some hazard sources are down"; only "none answered" is expressed
  (empty severity). `GET /v1/health` gives the detail.
- This API is for personal, non-commercial use: Open-Meteo's free API is limited to that. See
  [`docs/data-sources.md`](../data-sources.md).
